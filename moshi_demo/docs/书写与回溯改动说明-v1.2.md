# 书写手感 / 回溯语义 / 渲染性能 改动说明 v1.2

对应改动范围：`scripts/main.gd`、`scripts/water_renderer.gd`、`docs/player.md`，
新增测试 `tests/perf_probe`、`tests/rewind_consume_test`、`tests/dry_pen_hold_test`。

---

## 一、墨尽不收笔：出刀时机还给玩家

### 老行为

右键书写时，`_update_spell` 每帧检查余额，一旦 `tv < bullet_exit_tv(10)` 且起笔已超过
`bullet_min_time(0.2s)`，**直接替玩家调 `_end_draw()`** —— 线还没画完，人已经斩出去了，
子弹时间同时结束。墨用光的瞬间失控，是这套书写玩法最劝退的一处。

### 新行为

墨尽只把笔尖标成干涸，其余什么都不做：

```gdscript
func _update_spell(delta: float) -> void:
	spell_timer += delta
	tv = maxf(tv - BULLET_TV_DRAIN * delta, 0.0)
	if tv <= 0.0:
		dry_pen = true
```

于是干涸之后：

| 方面 | 结果 | 靠什么保证 |
|---|---|---|
| 是否自动斩出 | **否**，状态留在 `State.SPELL` | 删掉了强制 `_end_draw` |
| 子弹时间 | **继续**，怪物恒定 `bullet_factor`(0.10) 倍速 | `enemy_speed_factor()` 按 `State.SPELL` 分支返回 |
| 还能不能画线 | **不能**，鼠标怎么动都不落笔 | `_sample_ink()` 开头 `if ink_path.is_empty() or dry_pen: return` |
| 墨会不会自己回来 | **不会** | `_regen()` 只在 `State.PLAY` 里回墨 |
| 什么时候冲刺 | **松开右键**，沿已画好的轨迹走 | `_input` 右键抬起 → `_end_draw` → 匹配神纹 → `_begin_dash` |

玩家因此可以「写完 → 干涸 → 在慢镜头里从容看清战场 → 挑准时机松手」。

### 配置项影响

`data/player.tres` 的两个字段语义变了，`docs/player.md` 已同步：

- `bullet_min_time`：**已停用**（原本是自动收笔的最短保护时间，现在没有自动收笔了）。
  字段与镜像变量保留，避免动总表结构。
- `bullet_exit_tv`：现在**只**用作起笔门槛（`_begin_draw` 里 `tv < BULLET_EXIT_TV` 直接不起笔），
  不再是收笔阈值。

## 二、地上的线 = 下一次 R 会走的路

### 问题

`rewind_hist`（回溯航道）在 `main.gd` 里**从来没有被清空过**，只在 `_begin_dash` 里按
`rewind_slots()` 裁过长度。结果是：回溯用掉的那几段仍然画在地上，加上上一次冲刺留下的
`ink_path` / `dash_done` 水痕，玩家看到的线和「按 R 实际会倒着走的路」对不上。

### 改法

回溯走完的那一刻，把这批轨迹连同地面痕迹一起吃掉：

```gdscript
func _update_rewind(delta: float) -> void:
	if rewind_i < 0 or rewind_i >= rewind_hist.size():
		_consume_rewind_hist()
		_begin_burst(true)
		return
	...

## 回溯走完 = 这些轨迹被吃掉了：航道链、地上水痕一并清空。
func _consume_rewind_hist() -> void:
	rewind_hist.clear()
	rewind_i = -1
	rewind_d = 0.0
	ink_path = PackedVector2Array()
	ink_ages = PackedFloat32Array()
	dash_done = PackedVector2Array()
	dash_ages = PackedFloat32Array()
```

**约定**：地图上留着的线，永远严格等于「下次按 R 会倒走的路」。用完即消失，正常回溯结束后
地面不留任何轨迹；航道为空时按 R 不进 `State.REWIND`。

## 三、渲染性能：46ms → 1.7ms

### 定位过程

`tests/perf_probe` 逐层关显示做减法（A 全开 / A1 关背景 / A2 再关 HUD / A3 再关特效），
结论是空场 46ms 里有 44.8ms 是**背景水面**。进一步测得：兼容渲染器（GTX 1650 SUPER）下
每个 `draw_*` 都是独立 canvas item，约 **25µs/次**——瓶颈是**draw call 个数**，不是填充率。
一块底纹要 70+ 次 draw，视野内 20 多块，正好凑出 45ms。

### 四处改动

1. **背景块离屏缓存**（`_build_bg_tiles` / `_refresh_bg_tiles` / `_paint_bg`）
   4 个 `SubViewport` 各渲一种底纹变体，主层只 `draw_texture_rect` 平铺，
   按 `posmod(i*7 + j*13, 4)` 错开避免肉眼可见的重复；每帧至多重刷一块
   （`BG_TILE_REFRESH = 0.4s` 转一轮）来维持漂移动画。

2. **缎带整条批提交**（`water_renderer.gd: ribbon_gradient` / `batch_circles`）
   原本逐段 `draw_polygon`、逐点 `draw_circle`，一条尾迹上千次调用。
   改成一次 `RenderingServer.canvas_item_add_triangle_array()`；焦散改 `draw_multiline_colors`。

3. **点数预算**（`MAX_INPUT_PTS = 200` / `MAX_SMOOTH_PTS = 400`）
   `decimate()` 等距抽稀（首尾必留），并在 Chaikin 平滑前按 `1 << iters` 预估膨胀量、
   不够就降迭代次数。左键斩的补点间距也从 6px 放宽到 `SLASH_SAMPLE_DIST = 28px`
   —— 首尾锥化按路径**比例**算，与点数无关，密到 6px 纯属白烧 draw call。

4. **回溯只画当前段**（`_paint_ink`）
   整条航道链逐段全量重绘要 1.4 万三角形/帧；改成只给「正在倒走的那一段」上水痕，
   其余段由常驻航道导引线交代，信息不减。

### 实测（帧时，越低越好）

| 场景 | 改前 | 改后 |
|---|---|---|
| A 空场全开 | 46 ms | **1.68 ms** |
| B PLAY + 4 段航道 | 67 ms | **7.18 ms** |
| C DASH | 66 ms | **10.41 ms** |
| D REWIND | 133 ms | **12.96 ms** |

### 附带修掉的报错

`Invalid polygon data, triangulation failed.` —— 反弹路径在墙上 180° 对折会生成针状三角形。
`tri()` 的退化判定改成「按最长边算出的最小高 < 0.5px 就跳过」，比原先的面积阈值稳。
